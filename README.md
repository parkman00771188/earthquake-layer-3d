# 일본 주변 지진 4D (1975–2026)

일본과 주변 해역의 지진을 3차원 공간 + 시간축으로 보여주는 로컬 웹 시각화입니다. 점이 시간
순서대로 쌓이면서 **어느 장소, 어느 깊이에 지진이 집중되는지**가 입체적으로 드러납니다 —
일본해구를 따라 서쪽으로 파고드는 태평양판, 이즈-오가사와라 해구의 680 km 심발지진대
(와다치-베니오프 대)가 그대로 보입니다.

## 데이터 소스 — 두 개를 이어 붙입니다

```
1975 ──────────── ISC Bulletin (JMA 포함) M2.0+ ──────────── 2024-10 ── USGS M3.0+ ── 현재
```

일본 주변 소규모 지진을 보려면 소스가 둘이어야 합니다:

- **USGS ComCat** 은 어제까지 최신이지만 이 지역에 **M3 미만이 한 건도 없습니다.**
  (M2.0+ / M2.5+ / M3.0+ 질의 결과 개수가 완전히 동일 — 실측 확인)
- 작은 지진은 **기상청(JMA)** 이 관측하고, 그 데이터가 **ISC**(국제지진센터) 정식 회보로
  들어오면서 **M2.0까지** 완전해집니다. 다만 약 20개월 지연됩니다.

그래서 `config.json`의 `catalog.handoff` 날짜를 기준으로 앞은 ISC, 뒤는 USGS를 씁니다.
두 구간이 시간상 겹치지 않으므로 같은 지진이 두 소스의 서로 다른 ID로 중복될 일이 없습니다.

경계 이후 구간은 하한이 M3으로 올라가므로 **작은 지진이 빠집니다.** 시간바에 보라색 점선으로
표시되고, 패널 하단에 경고 문구가 뜹니다. ISC가 JMA 데이터를 더 공개하면
`update.bat --detect-handoff` 로 경계를 앞당기고 그만큼 M2대를 채울 수 있습니다.

## 1. 실행

```
serve.bat
```

브라우저가 `http://localhost:8080` 으로 열립니다. 포트를 바꾸려면 `serve.bat 9000`.

> **`index.html`을 파일로 직접 열면 동작하지 않습니다.** ES 모듈과 `fetch()`가 `file://`
> 에서 차단되기 때문에 반드시 로컬 서버를 거쳐야 합니다.

Python이 없다면 다른 정적 서버도 됩니다 (`npx serve`, VS Code Live Server 등).
프로젝트 루트를 문서 루트로 지정하면 됩니다.

## 2. 조작

| | |
|---|---|
| 드래그 | 회전 |
| 휠 | 확대 / 축소 |
| 우클릭 드래그 | 이동(팬) |
| 점 클릭 | 지진 상세 정보 (규모·깊이·시각·기관 링크) + 위치 표식 |
| 왼쪽 목록 클릭 | **해당 위치로 카메라 이동** + 링 표식 + 상세 카드 |
| `Space` | 재생 / 일시정지 |
| `←` `→` | 30일 이동 (`Shift` +365일) |
| `R` | 시점 초기화 |
| `Esc` | 상세 카드 닫기 |

### 표시 방식

- **누적** — 기간 시작부터 현재 시점까지 모든 지진이 남습니다. 밀집 구역을 보는 용도.
- **이동 구간** — 현재 시점에서 뒤로 정해진 기간만 표시합니다. 여진 전개나 활동 이동을 보는 용도.

### 기간 설정

- 패널의 **기간** 항목에서 시작·끝 날짜를 직접 입력하거나, `전체 / 최근 10년 / 최근 1년` 선택
- 아래 시간바의 **주황색 손잡이**를 좌우로 끌어서 조절
- 선택한 기간만 그려지고 재생도 그 안에서 반복됩니다

### 최근 지진 목록

화면 왼쪽의 **최근 지진** 패널은 현재 시점 기준으로 **바로 이전 50건**을 최신순으로 보여줍니다.
시간바를 끌거나 재생하면 목록이 따라 바뀌고, 규모·깊이 필터와 선택한 기간도 그대로 반영됩니다.

- 제목줄을 누르면 **접기 / 펼치기** (상태는 저장됩니다)
- 한 줄을 클릭하면 **카메라가 그 지진 위치로 부드럽게 이동**하고, 흰 링 표식이 찍히며
  상세 카드가 열립니다. 이동 중에 화면을 직접 드래그하면 이동이 취소됩니다.
- 왼쪽 숫자는 규모(규모 색), 오른쪽은 깊이(깊이 색 점)

### 지도

표면에 **땅이 채워진 지도**가 깔립니다. 패널의 **지도** 항목에서:

- **지도 (땅 채우기)** 켜기/끄기 + **지도 불투명도** 0–100% 슬라이더
- **해안선** / **행정 경계**(도·현·성) / **판 경계** / **깊이 상자·격자** 개별 토글

지진 점이 주인공이라 기본값은 50%입니다. 위에서 내려다보는 **위 (지도)** 시점에서 100%로
올리면 일반 지도처럼 보이고, 0%로 내리면 점만 남습니다.

지도는 **지진 점을 가리지 않습니다.** 표면 평면이 깊은 지진을 덮어버리면 안 되므로 깊이
테스트를 끄고 가장 먼저 그립니다 — 위에서 봐도 700 km 지진이 그대로 보입니다.

### 시각 조정

점이 흐릿하게 보이면 **선명도**를 올리세요 (100% = 또렷한 원, 0% = 부드러운 발광).
겹쳐진 밀도를 강조하려면 **발광 합성**을 켜고 색상 기준을 **밀도**로 두면 됩니다.

**깊이 과장**은 깊이 축을 몇 배로 늘려 볼지 정합니다. 1× 가 실제 비율이지만, 가로 3,000 km ×
깊이 700 km 라서 1×에서는 판이 눌려 보입니다. 기본값 2.5× 가 섭입 각도를 읽기 좋습니다.

### 설정 저장

패널의 모든 설정, 선택한 기간, 왼쪽 목록의 접힘 상태, 카메라 위치는 **브라우저에 자동 저장**되어
다음 접속 때 그대로 복원됩니다. 기본값으로 돌리려면 패널 맨 아래 **초기화** 버튼을 누르고
새로고침하세요.

## 3. 데이터 갱신

```
update_global.bat
```

일본과 전세계 데이터를 **한 번에** 최신화합니다: 일본(USGS 증분) → 전세계(USGS + ISC,
최근 며칠 구간을 되감아 다시 수집) → 빌드 → **무엇이 추가/수정됐는지 요약 출력** 순으로
진행됩니다. 보통 1~2분이면 끝납니다. 완료 후 브라우저에서 **Ctrl+F5**로 새로고침하세요.

전세계 수집은 매 실행마다 마지막 시점에서 USGS 7일 / ISC 14일을 되감아 다시 받습니다.
최근 지진의 진원 해는 며칠에 걸쳐 수정·추가되기 때문에, 꼬리 구간을 신뢰하지 않고
갈아끼우는 방식입니다. 실행이 끝나면 소스별 신규/수정/삭제 건수와 M5.5 이상 신규 지진
목록이 출력됩니다.

| 명령 | 설명 |
|---|---|
| `update_global.bat` | **일본 + 전세계 한 번에 갱신** (평소에는 이것 하나면 충분) |
| `update.bat` | 일본만 증분 갱신 |
| `update.bat --full` | 전체 기간 재수집 (지역/최소규모를 바꿨을 때) |
| `update.bat --resume` | 중단된 수집을 마지막 체크포인트부터 이어서 |
| `update.bat --build-only` | 다시 받지 않고 빌드만 |
| `update.bat --changes` | 마지막 갱신에서 **무엇이 바뀌었는지** 다시 출력 |
| `update.bat --detect-handoff` | ISC의 JMA 수록 시점을 다시 찾아 경계를 앞당김 |

평소 갱신은 **USGS 구간(경계 이후)만** 다시 받으므로 몇 초면 끝납니다. ISC 구간은 정적이라
경계가 움직일 때만 손댑니다.

`--detect-handoff` 는 ISC에 M3 미만 지진이 몇 건 있는지 월 단위로 이진 탐색해서(약 6번 질의)
JMA 수록 경계를 찾습니다. 경계가 앞당겨지면 그 구간의 USGS 행을 지우고 ISC M2+로 교체합니다.
ISC 지연이 약 20개월이므로 **반년에 한 번쯤** 실행하면 충분합니다.

### 무엇이 바뀌었는지 확인하기

갱신할 때마다 **기존 데이터와 비교해서 어떤 지진이 새로 들어왔고, 어떤 값이 어떻게 바뀌었는지**를
기록합니다. 실행 직후 콘솔에 바로 나오고, 나중에 `update.bat --changes` 로 다시 볼 수 있습니다.

```
[changes] 1 new | 2 revised | 0 metadata-only

  NEW (1)
    + 2026-07-01 16:15  M4.7     58km  50 km ENE of Kuji, Japan  [us6000t9fz]

  REVISED (2)
    ~ 2026-07-01 12:08  M6      54 km ENE of Noda, Japan  [us6000t9ej]
        mag        3.0  ->  6
    ~ 2026-07-01 14:47  M4.1    Bonin Islands, Japan region  [us6000taxk]
        latitude   30.0  ->  27.9874
        depth      999  ->  425.29
```

같은 내용을 **사이트에서도** 볼 수 있습니다. 오른쪽 패널의 **최근 갱신 내역** 에 요약이 뜨고,
`내역 보기` 를 누르면 항목별 목록이 펼쳐집니다. 한 줄을 클릭하면 그 지진 시점으로 이동해서
3D 화면에 표시해 줍니다.

네 가지로 분류합니다:

| 분류 | 뜻 |
|---|---|
| **신규** | 기존 카탈로그에 없던 지진 |
| **수정** | 발생시각·위치·깊이·규모·지명이 바뀐 지진 (바뀐 항목과 이전/이후 값을 함께 기록) |
| **대체** | 소스 경계가 앞당겨져 USGS 행이 ISC 행으로 교체된 경우 |
| **메타데이터만** | 기관이 레코드를 손댔지만 지진 해(解)는 그대로 — 화면에 아무 변화 없음 |

한 번에 1만 건 넘게 들어온 경우(전체 재수집)는 개별 목록을 생략하고 건수만 보고합니다.
백만 줄을 나열하는 건 정보가 아니라 소음이라서입니다. **수정** 목록은 이때도 유지됩니다.

전체 기록은 `data/raw/last_changes.json` (마지막 실행분, 최대 400건)과
`data/raw/update_history.log` (매 실행 1줄 요약)에 남습니다.

증분 갱신은 마지막 지진 시각에서 **45일 뒤로 겹쳐서** 다시 받습니다. USGS는 발생 후에도
진원 위치와 규모를 여러 차례 수정하기 때문에, 이 겹침 구간이 수정분을 따라잡습니다.
카탈로그는 `소스:이벤트ID` 로 키를 잡고 병합하므로 같은 구간을 몇 번 받아도 중복이 생기지 않습니다.

수집은 **1년 단위로 체크포인트**를 남깁니다. 중간에 끊겨도 최대 1년치만 다시 받으면 되고,
`--resume`이 정확히 그 지점부터 이어갑니다. 실행 기록은 `data/raw/update_history.log`에 쌓입니다.

### 자동 갱신 + 자동 배포 (30분마다)

```
auto_update_start.bat      켜기  — 지금부터 30분마다 갱신 → GitHub 업로드 → 웹 반영
auto_update_stop.bat       끄기  — 등록된 자동 갱신 제거
```

`auto_update_start.bat`을 한 번 실행하면 Windows 작업 스케줄러에 등록되어, **컴퓨터가
켜져 있고 로그인되어 있는 동안** 30분마다 조용히(창 없이) 다음을 수행합니다:

1. 일본 + 전세계 데이터 갱신 (`update_global.bat auto`)
2. GitHub 업로드 → 몇 분 뒤 웹사이트 반영

진행 상황은 `data\raw\auto_update.log` 에 기록됩니다. 자동 업로드는 `[auto]` 커밋
하나를 계속 덮어쓰는 방식이라 저장소 용량이 무한히 늘지 않으며, 변경이 없으면
업로드 자체를 건너뜁니다. 직접 만든 커밋(`upload.bat`)은 절대 덮어쓰지 않습니다.

재부팅 후에도 등록은 유지됩니다(로그인하면 다시 30분 주기로 동작).
끄고 싶을 때 `auto_update_stop.bat`을 실행하면 됩니다.

## 4. 수집 범위 바꾸기

`config.json`을 고치고 `update.bat --full`을 실행하면 됩니다.

```json
{
  "region": { "minlatitude": 22, "maxlatitude": 48,
              "minlongitude": 120, "maxlongitude": 152 },
  "catalog": { "starttime": "1975-01-01", "handoff": "2024-10-01" },
  "sources": {
    "isc":  { "minmagnitude": 2.0, ... },
    "usgs": { "minmagnitude": 3.0, ... }
  }
}
```

- **`sources.isc.minmagnitude`** 가 데이터 양을 지배합니다. M2.0에서 **1,227,741건**이고,
  M1.5로 내리면 수백만 건이 되어 브라우저가 버티기 어렵습니다. 가볍게 쓰려면 M3.0으로
  올리세요 (약 30만 건).
- **`sources.usgs.minmagnitude`** 를 M3 아래로 내려도 의미가 없습니다. USGS는 이 지역
  M3 미만이 0건입니다.
- 수집 스크립트가 요청당 한계에 맞춰 기간을 자동으로 반씩 쪼개므로, 어떤 값을 넣어도
  동작 자체는 합니다.
- `region`을 넓히면 `data/raw/` 의 기준 지형 파일(`ne_coastline`, `plates`, `ne_10m_land`,
  `ne_10m_lakes`, 행정 경계)은 그대로 두어도 됩니다. 빌드 때 새 경계에 맞춰 다시 잘리고
  지도 래스터도 다시 구워집니다.

전체 재수집은 ISC 구간 때문에 **약 2.5시간** 걸립니다 (연 단위 요청, ISC 서버가 느립니다).
ISC는 응답을 55,000건으로 제한하므로 밀집한 연도는 자동으로 반씩 쪼개 받습니다
(2011년 도호쿠 여진은 3조각, 83,674건).
1년마다 체크포인트를 남기므로 중단해도 `update.bat --resume` 으로 이어집니다.

├─ serve.bat             로컬 서버 실행
├─ update.bat            데이터 갱신
├─ config.json           수집 지역 · 소스별 최소 규모 · 소스 경계
├─ css/style.css
├─ js/
│  ├─ main.js            앱 조립 · UI 배선 · 재생 루프
│  ├─ data.js            meta/bin/labels/basemap 로딩
│  ├─ projection.js      경위도 → 장면 좌표
│  ├─ quakeLayer.js      123만 점 포인트 클라우드 + 셰이더
│  ├─ refLayer.js        지도(땅) · 해안선 · 행정/판 경계 · 깊이 격자 상자

│  ├─ feed.js            최근 지진 목록 · 갱신 내역 목록
│  ├─ marker.js          선택된 지진 위치 링 표식
│  ├─ picking.js         커서 → 지진 검색
│  ├─ palette.js         색상 램프 (셰이더/범례/목록 공용)
│  └─ store.js           설정 저장

언제든 `update.bat --build-only`로 다시 만들 수 있습니다.

### quakes.bin 형식 (버전 2)

리틀엔디언, 16바이트 헤더 (`"JQ4D"` + 버전 u32 + 개수 u32 + 예약 u32) 뒤에
**시간 오름차순으로 정렬된** 배열 9개가 이어집니다:

| 배열 | 형식 | 내용 |
|---|---|---|
| `lon` | Float32 × N | 경도(도) |
| `lat` | Float32 × N | 위도(도) |
| `depth` | Float32 × N | 깊이(km) |
| `mag` | Float32 × N | 규모 |
| `t` | Uint32 × N | `meta.epoch`부터의 초 |
| `place` | Uint16 × N | `labels.json` → `places` 색인 |
| `magType` | Uint16 × N | `labels.json` → `magTypes` 색인 |
| `extId` | Uint32 × N | ISC 이벤트 번호, 또는 `usgsIds` 색인 |
| `src` | Uint8 × N | 0 = ISC, 1 = USGS (맨 끝 — 4바이트 정렬 유지) |

정확한 바이트 오프셋은 `meta.json`의 `binary.arrays`에 들어 있습니다.

**지명은 사전 압축합니다.** 123만 건에 지명 문자열을 그대로 넣으면 50 MB가 넘는데, ISC는
Flinn-Engdahl 권역명을 쓰기 때문에 **서로 다른 지명이 수백 개뿐**입니다. 그래서 이벤트마다
2바이트 색인만 두고 사전을 따로 둡니다 — 고유 지명 2,055개, `labels.json` 99 KB입니다.

**시간순 정렬이 핵심입니다.** "시작부터 T까지" 와 "T에서 뒤로 N일" 이 둘 다 **연속된 인덱스
구간**이 되기 때문에, 재생은 매 프레임 `setDrawRange()` 호출 한 번으로 끝납니다. 규모·깊이
필터와 색·페이드는 정점 셰이더에서 처리하므로 123만 점이 draw call 하나에 그려집니다.

### land.png (지도 레이어)

육지를 폴리곤 메시로 그리려면 구멍(호수·내해) 처리가 되는 삼각분할기가 필요하고, 10 m 해상도
일본은 섬이 수천 개입니다. 그래서 빌드 때 **그레이스케일 마스크 PNG로 굽습니다** — 텍스처 하나,
draw call 하나, 그리고 불투명도가 그냥 재질 속성 하나가 됩니다. 슬라이더가 원하는 형태죠.

- 스캔라인 채우기 + **even-odd 규칙** — 외곽선과 구멍을 한 목록에 넣으면 호수가 자동으로
  파이고, 섬 안의 호수 안의 섬 같은 중첩도 방향(winding) 추적 없이 맞습니다.
- **활성 에지 테이블(AET)** 로 O(에지 + 교차점). 모든 스캔라인이 모든 에지를 검사하면
  6.4만 에지 × 3,328줄 = 2억 번이라 파이썬으로는 몇 분이 걸립니다. AET로는 **2초**입니다.
- 채우기는 `bytearray` 슬라이스 대입이라 픽셀 단위 루프가 없습니다 — 그래서 4096×3328 같은
  큰 텍스처도 비용이 거의 안 듭니다.
- PNG는 `zlib` + `binascii.crc32` 로 직접 씁니다(약 30줄). Pillow도 GDAL도 필요 없습니다.
- 육지 마스크는 압축이 아주 잘 됩니다: 13.6 M 픽셀 → **56 KB**.

행 0이 최북단이라 three.js의 `flipY` 기본값과 맞물려 `v=1`이 북쪽이 됩니다. 별도 뒤집기가
필요 없습니다.

한 가지 함정: 셰이더에 넘기는 시간 속성은 Float32인데, 50년 카탈로그 끝부분에서 Float32의
해상도가 약 5×10⁻⁴일(≈45초)로 벌어집니다. 그래서 **인덱스 이진 탐색은 Float64 사본**으로
합니다. Float32로 탐색하면 가장 최신 지진 몇 건이 조용히 빠집니다.

## 6. 알아둘 점

**"진도"가 아니라 "규모"입니다.** 이 시각화는 규모(Magnitude) 기준입니다. 일본 기상청이 쓰는
**진도(震度, shindo)** 는 관측 지점마다 다른 흔들림의 세기라서 지진 하나에 값이 하나로 정해지지
않고, 3D 점 하나로 표현할 수 없습니다. 국제 카탈로그가 제공하는 값도 규모입니다.

**연도별 "발생 빈도"를 비교하는 데는 쓰지 마세요.** 시간바 히스토그램의 증감은 상당 부분
관측망과 수록 방식의 변화입니다. 확인된 것만 셋:

| 구간 | 원인 |
|---|---|
| 1975–1990년대가 낮음 | 관측망이 성기던 시기 — 작은 지진이 기록 자체가 안 됨 (1975년 약 2,700건 → 2015년 약 32,800건) |
| 2024-10 이후 급락 | **소스 전환**. 하한이 M2 → M3으로 올라감 (보라색 점선) |
| 2011년 3월 급증 | 이건 진짜입니다 — 도호쿠 M9.1 여진 |

공간·깊이 분포(어디에 어느 깊이로 판이 파고드는지)를 보는 목적에는 문제가 없습니다.
그게 이 사이트의 용도입니다.

**규모 종류가 섞여 있습니다.** JMA의 `M`, 그리고 `mb`, `mww`, `ms`, `ml`, `MW` 등 서로 다른
방식으로 산출된 규모가 한 카탈로그에 들어 있습니다. 종류가 다르면 같은 숫자라도 정확히 같은
크기가 아닙니다. 상세 카드에 각 지진의 규모 종류가 표시됩니다.

**깊이 정확도.** 원격 관측만으로 결정된 깊이는 오차가 큽니다. 관측 기관이 깊이를 제약하지 못한
경우 0 km, 10 km, 35 km 같은 기본값이 들어가는 일이 있어, 그 깊이에 점이 인위적으로 몰려
보일 수 있습니다. 위에서 내려다보는 시점에서 유독 얕은 점이 격자처럼 깔려 보이면 그 영향입니다.

**지명 정밀도가 소스마다 다릅니다.** ISC는 Flinn-Engdahl 권역명(`Near east coast of eastern
Honshu` 같은 수백 개의 광역 이름)을, USGS는 `10 km WNW of Honmachi, Japan` 처럼 구체적인
이름을 씁니다. 그래서 목록에서 경계를 넘어가면 지명이 갑자기 뭉뚱그려집니다.

## 7. 문제 해결

| 증상 | 확인 |
|---|---|
| "데이터를 불러올 수 없습니다" | `serve.bat`으로 띄운 뒤 `http://localhost:8080` 접속. `file://`로는 안 됩니다. |
| 화면이 검게만 나옴 | 브라우저 WebGL 지원 확인 (`chrome://gpu`). 하드웨어 가속을 켜 두세요. |
| 갱신했는데 그대로 | **Ctrl+F5** 로 강력 새로고침. |
| 수집이 중간에 끊김 | `update.bat --resume` (1년 단위 체크포인트부터 이어감) |
| 처음 로딩이 느림 | `quakes.bin` 이 35.6 MB입니다. 로컬 서버라면 수 초, 진행률이 표시됩니다. 더 가볍게 하려면 `config.json`의 `sources.isc.minmagnitude`를 3.0으로. |
| 최근 2년이 비어 보임 | 정상입니다 — 소스 전환 때문입니다. `update.bat --detect-handoff` 로 ISC가 새로 공개한 만큼 채울 수 있습니다. |
| 점이 너무 흐림 | 패널 → 시각 → **선명도** 를 올리고 **불투명도** 를 100%로. |
| 설정이 이상해짐 | 패널 맨 아래 **초기화** → 새로고침. |
